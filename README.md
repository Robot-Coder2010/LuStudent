# Latter UP Student Portal
Static site (Netlify) + Supabase (login, database, file storage).
Content is edited at `/admin.html` — no code changes needed. For a new database, run `supabase/setup.sql`, then `supabase/update-2-names.sql`, `supabase/update-4-portal-customization.sql`, `supabase/update-5a-leadership-team.sql`, `supabase/update-5b-email-alerts.sql`, `supabase/update-6-students-list.sql`, `supabase/update-7-bug-fixes.sql`, and `supabase/update-8-security-and-data-fixes.sql` in order. Existing databases should apply any missing updates in order. The last updates add scheduled publishing rules, public portal settings, secure video IDs, and other RLS fixes.

Deploy both Supabase Edge Functions in `supabase/functions/`: `import-students` and `change-own-password`. In Supabase Authentication settings, disable public sign-ups because accounts are provisioned by admins, enable email confirmation for any remaining signup flow, and configure CAPTCHA for anonymous sign-ins before enabling the public photo page. To allow photo submissions without a visitor account, also enable **Anonymous Sign-Ins**; the page uses a persistent anonymous session and the photo cap is enforced per visitor session.

Student accounts are created from Admin → Import students. The random starting-password option is selected by default; it is safer than sharing one password across many accounts. The first-password-change flag is stored in protected app metadata and enforced by database access policies, then cleared by the `change-own-password` Edge Function.
Only edit config.js if the Supabase project changes (anon key is public by design; never use the service_role key).

For local testing, serve the folder over HTTP instead of opening `index.html` directly from disk. From the project folder in PowerShell, run `py -m http.server 8000` (or `python -m http.server 8000`), then visit `http://localhost:8000`. Browsers do not reliably share authentication storage between pages opened with `file://`.

On `localhost` or `127.0.0.1`, open the profile menu and choose **Use local preview** to show sample announcements, video thumbnails, photo galleries, and the read-only admin preview. Choose **Exit local preview** to return to the normal signed-out or signed-in site view. Preview mode and its admin screen use sample data only and never grant Supabase permissions or write to Supabase. All sample files are kept in `PLACEHOLDER/` and are ignored automatically on deployed hosts. To exclude the preview from a Netlify deploy, remove the `PLACEHOLDER/preview.js` script tag from `index.html`, `announcements.html`, `videos.html`, and `photos.html` and the preview loader from `admin.html`, then exclude the `PLACEHOLDER/` folder. The regular site does not depend on any files in `PLACEHOLDER/`.


Portal customization: run `supabase/update-4-portal-customization.sql` in Supabase SQL Editor (safe to rerun). It adds the `portal_banner`, `portal_tiles`, and `portal_home_sections` columns and refreshes the Supabase schema cache. Then deploy the site files and open Admin → Portal Layout to edit the announcement banner and tiles, or Admin → Home page editor to show/hide and reorder home page sections. The home page tile grid requires `portal-card-grid` in `index.html`, which is included in this version. These settings are stored in Supabase and persist when website source files are replaced.
